# AgentBOM v1

AgentBOM v1 is the interchange format for describing an AI agent security graph.

## Purpose

The document format separates **what was observed** from **what the engine concluded**. It is designed to be generated by AgentBOM and consumed by scanners, CI systems, policy engines, graph databases, and other security tooling.

## Required top-level sections

```json
{
  "schema_version": "1.0",
  "document": {"id": "...", "created_at": "..."},
  "entities": [],
  "relationships": [],
  "evidence": []
}
```

### Entities

Entities represent first-class objects such as:

- `agent`
- `model`
- `tool`
- `mcp_server`
- `identity`
- `credential`
- `permission`
- `data_source`
- `deployment`

Every entity has a stable `id`, `kind`, and `name`. Provider-specific information lives under `properties`.

### Relationships

Relationships describe security-relevant edges. Examples include:

```text
USES
DELEGATES
ASSUMES
IMPERSONATES
GRANTS
ACCESSES
CONNECTS_TO
DEPENDS_ON
DEPLOYED_AS
```

Relationship properties may contain provider metadata and provenance.

### Evidence

Evidence records why an entity or relationship exists. Evidence should identify its source and, where available, an observation time and confidence score.

## Authority model

AgentBOM treats delegation as transitive authority rather than merely an inventory relationship.

```text
User
  ↓ delegates
Agent A
  ↓ delegates
Agent B
  ↓ grants
Permission
  ↓ accesses
Resource
```

The Rust engine resolves effective authority across bounded delegation hops and can correlate that inherited authority with reachable security resources.

```bash
agentbom authority ./mcp.json agent-a
agentbom authority ./mcp.json agent-a --findings
agentbom attack-paths ./mcp.json agent-a
agentbom attack-paths ./mcp.json agent-a --findings
```

A correlated finding can now preserve the complete evidence chain rather than reporting the permission and resource independently.

## Generating a v1 document

```bash
agentbom spec ./mcp.json --output agentbom.json
```

The generated file is validated against `schema/agentbom-v1.schema.json` by downstream tooling.

## Compatibility

The schema intentionally permits provider-specific data inside `properties` while keeping entity kinds and relationship semantics stable. Breaking changes require a new major schema version.
